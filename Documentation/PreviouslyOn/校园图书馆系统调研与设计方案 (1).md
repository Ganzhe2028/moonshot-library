# 校园图书馆系统调研与设计方案

## 一、调研结果：市面优秀方案与启发

1. 常见用户流程（User Flow）

- **借书流程**：登录 → 搜索图书 → 查看可借状态 → 借阅 → 查看借阅记录
- **还书 / 续借流程**：提醒 → 用户确认还书或申请续借 → 系统更新状态
- **预约流程**：若图书被借出 → 发起预约 → 归还后系统通知取书
- **新书推荐**：用户填写推荐 → 馆员审核 → 入库
- **后台流程**：用户管理、图书管理、借阅统计、逾期管理

1. 痛点与优化方向

| 痛点           | 设计机会                                 |
| -------------- | ---------------------------------------- |
| 不知道库存状态 | 图书状态标签（在馆 / 已借 / 预约中）     |
| 忘记还书       | 自动提醒机制（到期前 / 到期日 / 逾期后） |
| 操作繁琐       | 一键借还 / 移动端扫码借还                |
| 后台繁琐       | 自动报表、可视化数据仪表盘               |
| 用户黏性低     | 推荐系统 / 新书征集 / 评价机制           |

1. 成熟方案的**共性**

- **明确角色**分层（学生、教师、管理员）
- **全流程状态反馈与提醒**系统
- **预约与续借**机制闭环
- 逐步智能/**便捷化**（推荐算法、**自助借还**）

## 二、我校图书借阅系统设计设想

1. 场景与目标

- 服务对象：学生 / 教师 / 馆员
- 目标：**简化借还**、减少人工、提升体验
- 技术现状：团队人少、基础有限 → 优先设计简单直观的 User

💡 设计目标
• 让借书、还书、预约等操作一目了然
• 减少馆员人工工作量
• 支持未来扩展（如扫码借还、个性推荐）

Flow

1. 用户流程（简化版）

```GraphQL
A[登录系统] --> B[搜索图书]
B --> C{图书状态}
C -->|可借| D[借阅 → 确认 → 借出成功]
C -->|已借出| E[点击预约 → 排队等待]
D --> F[我的借阅 → 查看归还日期]
F --> G[还书 / 续借]
G --> H[系统更新状态]
E --> I[系统通知 → 来馆取书]
```

1. 不同角色的视角：

- **学生/教师端**：登录 → 搜索 → 借阅/续借/预约 → 我的借阅 → 提醒通知
- **馆员端**：图书管理、用户管理、预约审批、逾期管理、报表生成

## 三、版本规划（从 MVP 到 3.0）

| 版本 | 核心目标                 | 用户功能                           | 管理功能                   | 设计重点              |
| ---- | ------------------------ | ---------------------------------- | -------------------------- | --------------------- |
| MVP  | 可用原型，完成最基本借阅 | 登录 / 查书 / 借书 / 查看借阅      | 查看图书状态、人工登记还书 | 简洁界面、稳定流程    |
| 1    | 闭环化流程               | 借书 / 还书 / 续借 / 预约 / 提醒   | 预约与逾期管理、自动通知   | 增加状态反馈与提醒 UI |
| 2    | 数据化与用户参与         | 推荐书目、评分、用户推荐新书       | 数据仪表盘、推荐管理       | 增强交互与可视化体验  |
| 3    | 智能与移动化             | 扫码借还 / App/小程序 / 个性化推荐 | 自动分析与智能推送         | 无缝体验、跨平台整合  |

## 四、MVP 重点设计说明

### 借阅者视角

1. 登录 → 搜索图书（书名/作者）
2. 查看结果列表（含状态）
3. 若可借 → 点击借阅 → 系统生成借阅记录
4. 查看“我的借阅”页面：显示借阅中图书与归还时间

### 馆员视角

1. 登录后台 → 管理图书（在馆 / 已借 / 预约）
2. 管理借阅记录（借出 / 归还登记）
3. 生成基础报表（借阅数量、热门书）

## 五、后续版本设计要点

- **1.0**：增加“**提醒 + 续借 + 预约”形成完整闭环**
- **2.0**：加入“**推荐 / 评价** / 数据分析”提高活跃度
- **3.0**：支持“**扫码借还** / 智能推荐 / **推送通知**”，整合校园 App

## 六、风险与注意事项

- 确保库存状态实时同步（避免用户体验断层）
- 借阅规则清晰可见（上限、续借次数、罚款）
- 版本间逐步演进，避免一次性开发过多功能
- 上线初期提供“使用指引”或视频教程
- 收集用户反馈，定期优化 UI/UX

## 七、总结

本方案将图书馆借阅系统分阶段推进，让团队以 MVP 起步、逐步实现完整体验：

> 查书 → 借书 → 续借 / 预约 → 提醒 → 智能推荐 → 扫码借还

这种方式既能让新手成员理解整体系统逻辑，也能为学校提供长期可扩展的数字化借阅体验。
